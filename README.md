# 每日签到 · 烧饼与 NodeSeek

本地运行的 Chrome Manifest V3 扩展。支持每日定时尝试、手动一键签到、单站签到和只读状态刷新。烧饼留言可自定义并长期保存，首次默认 `666`。

## 0.1.7 · 登录提醒修复

安装包和 SHA256 校验文件见 [GitHub Releases](https://github.com/stone123-btn/daily-checkin-extension/releases)。

- 烧饼与 NodeSeek 均处理登录页跳转、登录表单及签到区域内的明确登录提示。签到表单或区域缺失时，会检查导航中的可见、同站登录入口；烧饼还识别签到区域之外的明确登录通知。没有明确未登录证据时，保留加载/失败判断，并提示检查登录，不把普通加载失败直接认定为登录过期。
- 需要登录时，卡片明确显示红色「需要重新登录」和「重新登录」入口，工具栏图标显示提醒数字。等待十分钟仍未处理，会保留「登录已超时」和重新登录指引。
- 桌面提醒默认关闭。点击弹窗的「开启提醒」并在 Chrome 授权后，才会发送系统通知；系统通知关闭或被系统屏蔽不影响卡片和图标提醒。
- 登录处理页优先打开当前需要登录的页面；未提交任务在有效等待期内返回签到页后可继续，只读任务仍不提交。此前已尝试提交的任务仅核对结果，不因重新登录而重复签到。

更新时替换原加载目录的文件，在 Chrome 扩展管理页点击「重新加载」，确认版本为 **0.1.7**。无需卸载，已保存的留言和时间会保留。扩展只在检查或执行任务时获知网站要求登录，不会在后台持续监控 Cookie 的过期时间。

## 安装

1. 解压 `daily-checkin-extension.zip` 到一个固定文件夹。
2. 在 Chrome 地址栏打开 `chrome://extensions/`，开启右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的 `daily-checkin-extension` 文件夹。
4. 将插件固定到工具栏。在**同一个 Chrome 用户配置**中登录 [烧饼](https://sb.sb/checkin/) 和 [NodeSeek](https://www.nodeseek.com/board)。
5. 打开插件，先点击「刷新状态」，确认识别结果，再点击「一键签到」。

直接加载源码目录也可使用，无须安装 Node 或构建。更新时覆盖原目录并在扩展管理页点击「重新加载」。不要删除或移动正在加载的目录。卸载可在扩展管理页点击「移除」。

## 超时后重新签到（0.1.6 起支持）

0.1.6 新增旧任务恢复入口，并分别记录留言准备、点击许可、实际点击和网站确认，便于区分「只核对」与「真正执行」。

1. 已安装用户请覆盖原加载目录，在扩展管理页点击「重新加载」，确认版本为 **0.1.7**。不要卸载，以保留已保存的留言、时间和任务记录。
2. 如果烧饼仍显示「验证已超时」或「结果待确认」，打开插件，找到**烧饼卡片**。升级会保留旧任务的防重复保护，不会自动重新提交。
3. 点击卡片内的 **「重新尝试」**。插件会先核对网站当前是否已签到；如果已签到，恢复直接结束。
4. 等确认框显示网站当前可签到，检查其中的重复操作提示，再点击 **「确认重新签到」**。只有核对结果未超过30秒时才能确认；过期请取消后重新尝试。
5. 插件使用最新已保存的留言创建新执行任务，重新填写并点击签到，等待网站确认。需要登录或人工验证时，在网站处理；以网站和插件的最终状态为准。

**「刷新状态」「核对结果」只查询，不填写、不点击。存在待恢复任务时，「一键签到」也只核对并提示恢复；需要重新执行时，请使用上述确认重试入口。**

更新扩展后，已经打开的旧网页可能无法继续回报结果。在原页处理后，可点击「核对结果」获取最新状态。旧版本已有不确定任务会自动迁移，尽可能从历史找回原始失败原因；历史被清除时保留「结果待确认」。

## 使用

- 默认每日 **09:00，新加坡时间 UTC+8** 自动尝试；在主弹窗直接选择时间并点击「保存时间」。两站共用一个每日时间，设置页仍可启停自动任务及选择网站。
- 时间确实改变时，未来的时间从今天生效；今天已经过去或正好到点的时间从明天生效。今天已自动执行的站点不会因为改时间再次发起。保存本身不签到，也不会开启已关闭的自动签到。仅修改留言或保存相同时间不改变原有补跑资格。
- 状态同时使用文字、符号与颜色区分：绿色勾号「今日已签到」、橙色空心圆「今日未签到」、蓝色执行中、红色需处理、灰色待检查或已停用。未知结果不会直接显示为未签到。
- Chrome 必须运行。浏览器关闭、电脑休眠时不会执行；下次启动或恢复后通过启动事件及每15分钟检查补跑当天任务，不追补历史日期。浏览器定时器可能延迟，不能保证整点执行。
- 「一键签到」或单站「签到」会创建独立的后台标签页。成功并确认仍为本次任务页后自动关闭；需要你处理或结果不明时保留页面。
- 「刷新状态」创建检查任务，**不填留言、不提交**。同站已有进行中的任务时只沿用该任务，不另开任务。
- 打开弹窗时，超过5分钟的历史结果会自动重新核对；只读查询不会覆盖等待重试的任务。卡片分别标明最近尝试时间和网站核对时间。
- 在插件「设置 → 网站与留言 → 烧饼固定签到留言」输入内容并点击「保存设置」。手动和定时签到都会持续使用该留言，直到再次修改并保存；修改但未保存不会生效。
- 留言只保存在当前 Chrome 用户配置中，关闭浏览器或重启电脑后保留；卸载插件、清除插件数据或换用户配置后需重新设置。不同网站账号若共用同一个 Chrome 用户配置，也共用此设置。
- 留言不能为空、只有空格、包含换行或控制字符，最多 120 个字符（按浏览器字符串长度计数，部分表情占多个字符）。无效输入会提示错误并保留原设置，不会静默截断。网站可能有额外长度或内容限制。
- 每次烧饼任务开始时固定本次留言，进行中修改设置从下一次新任务生效；当前任务和它的自动重试继续使用原留言。插件只在自己控制的执行页填写固定留言，即使该页已有其他内容也会替换；普通网站页面和只读状态查询不会改写留言。
- 烧饼会自动尝试点击已识别的原生验证按钮一次。验证失败、其他机器人验证、Cloudflare 验证或登录仍需你完成。插件图标显示提醒数字；点击「打开处理」进入任务页。未开启桌面通知时，弹窗提供「开启提醒」入口，点击后通过 Chrome 正式申请权限。
- 烧饼原生流程：插件填写本次固定留言并点击签到一次打开验证框，再点击已显示、唯一且可用的原生 CAP 按钮一次；验证通过后，**网站自身继续提交**，插件核对结果。两种点击许可分别先写入本地存储，后台重启或重复操作不会重复发放。只读任务不填写、不点击任何验证。插件不自行求解或生成验证 token，不修改网站的验证结果；正常点击不保证网站一定通过验证。
- 验证或登录等待10分钟后提示超时。烧饼原生验证超时明确显示「验证已超时」，「继续验证」返回原页面。原始任务和失败原因单独保存，之后的查询不会覆盖；原页稍后报告成功时，仍可结束恢复状态。原页面已关闭或离开签到页时会明确提示。
- 结果待确认时，普通「签到」仍只查询并提示「需要恢复」。点击「核对结果」会新建只读检查页，不填写、不点击，也保留原验证页；网站确认已签到便结束恢复。需要重新执行时点击「重新尝试」，插件会先核对最新状态，再显示确认框；仅当页面明确可签到，且核对结果未超过30秒时允许确认。加载中、需登录、结构不明或核对过期均不能确认。
- 确认「重新签到」后，插件停止并关闭仍有本次任务标记的原页和核对页，使用**最新已保存的留言**创建新执行任务；未保存草稿不生效。新任务仍只发放一次签到和一次原生验证点击许可，旧确认、旧页面消息不能重新发放。已导航到其他内容的标签页保留。网站已经收到的请求无法撤销，核对到可签到也不能证明旧请求未在处理中，因此重试前需用户明确确认可能重复操作的风险。
- 签到区域或表单尚未挂载、控件尚未加载、唯一按钮暂时禁用时，使用45秒加载窗口继续等待；提交前加载超时最多在5分钟、15分钟后重试两次。控件不唯一、结构冲突或按钮不明确时停止，交给人工确认。
- NodeSeek 按已核实的公开页面脚本，默认点击「鸡腿 x 5」领取固定5鸡腿。必须同时识别「今日还未签到」和固定、随机两按钮的完整结构；其他明确、唯一的签到按钮也可识别。未知结构或不明确的多个选项会停止并提示打开网站。插件完整自动流程仍需在真实未签到日验收。
- 调度日期使用新加坡时间；站点真实重置时间未核实。每天每次都读取当前账号的网站状态，不用本地成功缓存替代网站结果。首次安装建立下一次定时；需要立即执行请点击「一键签到」。
- 「导出诊断」保存计划时间、实际开始时间、尝试与成功记录、恢复原因、原任务ID、实际执行/只读模式、最近40条任务摘要，以及每个任务最近20条阶段和原因记录。新任务分别记录留言准备、签到许可、页面实际点击、验证许可、页面实际验证点击和网站成功时间；旧字段`submittedAt`/`verificationAttemptedAt`仍代表许可保留时间，不能作为HTTP提交成功的证据。页面跳转或中断可能导致点击回报缺失。导出不包含留言、原始页面HTML或账号凭据。

主弹窗的烧饼卡片始终显示「固定签到留言」输入框，即使今天已经签到也可修改。点击「保存留言」后，下次新任务起持续使用。留言和时间独立保存，未保存的输入不会用于签到，关闭弹窗会丢弃草稿。状态刷新保留草稿、焦点和光标；弹窗与设置页共用配置，未编辑字段自动同步，正在编辑的同一字段被其他页面修改时会提示，明确点击保存后才覆盖该项。

## 权限与数据

- `storage`：保存设置、任务状态和最近40条结果摘要；`alarms`：每日任务、重试和超时。
- 仅有 `https://sb.sb/*`、`https://www.nodeseek.com/*` 的站点访问权限。内容脚本只在签到路由加载，执行前再次检查域名与路径。
- `notifications` 为可选权限，只有你在设置页开启时才申请。
- 沿用网站在当前 Chrome 配置中的登录状态。无服务器，不读取或保存账号密码、Cookie、CSRF或验证码值；验证字段仅在页面内用于是否通过的布尔判断，不传回后台。
- 不使用远程代码、全站权限、Cookies API、浏览器调试权限，也不会关闭你原先打开的标签页。
- 卸载扩展会清除其本地存储。Chrome 无痕模式和多账号自动切换不在首版范围内。

## 已知限制

- 此次恢复流程用于在结果不明时安全地重新执行，不保证网站的人机验证一定通过。此前一次真实验证等待超时的具体原因尚未定位。
- 仍有一个已确认的并发问题：普通只读查询尚未结束时触发签到，执行请求可能只返回任务占用；定时碰撞也可能提前记为当天已处理。此版本未修复该问题，手动签到请等查询结束后再操作。
- 跨日定时提交、休眠或关闭浏览器后的补跑仍需长期实际使用验收。详细验证范围见 [VALIDATION.md](VALIDATION.md)。

## 开发与验证

公开仓库和安装包只包含运行文件与说明，不包含开发依赖、测试工程或浏览器配置。以下命令仅适用于含有 `package.json`、`scripts/` 和 `tests/` 的完整本地工程。开发需要 Node.js 20+、Python 3（仅重新生成图标时）和系统 `zip`。

```sh
npm ci
npx playwright install chromium
npm run check
npm test
npm run test:browser
npm run test:popup
npm run package
```

浏览器测试在自动删除的隔离临时配置中加载真实扩展，将两站请求替换为本地测试页面；不会使用实际 Chrome 账号或向真实网站签到。截图和机器可读报告输出到 `test-results/`。

打包只复制运行文件和说明至 `dist/daily-checkin-extension/`，ZIP 为 `dist/daily-checkin-extension.zip`。不包含依赖、测试、浏览器配置或浏览器会话。

主要文件：`background/tasks.js` 管理任务与一次性许可，`background/scheduler.js` 管理时间，`content/common.js` 观察页面并执行，两个站点适配器只负责识别，`ui/` 提供弹窗和设置。当前验证范围与待验收项见 [VALIDATION.md](VALIDATION.md)。
